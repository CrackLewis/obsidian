
## 函数调用

内联函数：
- 对于大部分行数较少的函数，使用`inline`。尽管`inline`在C++中有不同的含义，但内联思想很重要。过长的函数（50+行）不建议`inline`。
- `-O2/-O3`等优化开关可以使编译器自行决定内联优化幅度

传参优化：
- 对于非基本类型数据，尽量用引用/指针而非值传递
- 对于参数数量较多的函数，建议使用一个结构体包裹所有参数

辅助编译器执行优化决策：
- 对于函数执行期间不会改变的值，设置`const`
- 对于会独占所指内存访问权的指针，设置`restrict`
- 非成员函数/变量声明为`static`
- 在性能敏感的代码区段，慎用虚函数、`std::function`等
- 涉及多文件链接的场景，启用`-flto`

x86平台下，函数可采用灵活的调用约定：

| 调用规定          | 传参顺序                      | 堆栈清理方 | 用途               |
| ------------- | ------------------------- | ----- | ---------------- |
| `__cdecl`（默认） | 从右到左                      | 调用方   | C/C++默认约定，支持可变参数 |
| `__stdcall`   | 从右到左                      | 被调用方  | Win32 API默认约定    |
| `__fastcall`  | 前两个参数放入`ecx/edx`，其余从右到左入栈 | 被调用方  | 对性能要求高的场景        |


## 内存布局

尽量使用连续内存，相同时间段访问的内存尽量相邻，降低缓存的刷新率。

一维数组\>二维表

如果事先知道STL容器（`std::vector`等）的最大容量，可以用`reserve`预分配空间，避免内存反复申请/释放

如果程序时间要求比较极端，且确定STL不会重新分配内存，使用`data`方法访问裸地址，但可能不安全

bitset适合：
- 记录有限个元素是否存在
- 快速计算两个有限集合的交集

### 分支预测提示

现代CPU采用动态分支预测（Branch Prediction Unit）技术对条件跳转指令的走向预测。预测失败将清空流水线，产生约10-20 cycles的性能损失

GCC的`__builtin_expect(cond, val)`内建函数可以：
- 提示GCC`cond`更可能是什么（`val`取0或1）
- GCC将：
	- 执行概率更高的路径放在顺序分支（冷路径）
	- 执行概率更低的路径放在跳转分支（热路径）

```asm
cmp ...  ;被比较的条件
je  L1   ;相等则跳转至L1。先验认为，两个比较值相等概率低，因此将不相等分支放在顺序分支

;likely路径（比较值不相等，执行概率更高）
...
jmp L2

;unlikely路径（比较值相等，执行概率更低）
L1:
...

L2:
...
```

*作用*：对于错误判断等必要但不常触发的冷路径，可以通过提示GCC错误条件成立概率低，来规避热路径跳转的情况

```cpp
#define LIKELY(c) __builtin_expect(c,1)
#define UNLIKELY(c) __builtin_expect(c,0)

void foo(int x) {
	if (UNLIKELY(x < 0)) {
		// print error or something
	}
}
```
